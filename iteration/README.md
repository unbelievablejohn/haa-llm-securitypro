# 迭代过程：从零起步的每一步

> **这个文件夹是历史记录，不是最终产品。**
> 现在能用的系统在 [`../src/`](../src/) 里；这里保存的是它是怎么一步步长出来的。

---

## 为什么保留这些

这个项目是从**零基础**起步的。HAA 看重的不是"最后交出一个多复杂的系统"，
而是**从一个想法开始，一步步把它做出来的过程** —— 包括中间走过的弯路。

所以这里保留了每一天的原始脚本和运行日志。**即使它们很粗糙，也不删。**

---

## 逐日进展

### `day1.py` — 第 1 天：起步

```python
print("Hello,confidence and safety!")
print("I am starting from zero.")
```

**只有 689 字节。** 变量、输入、if 判断 —— 编程的最基础部分。

> 值得看的是第一行：`confidence and safety`（置信度与安全）。
> **项目最终要做的东西，在第一天的那句 Hello 里就已经写下了。**

### `day2.py` — 第 2 天：第一次写出"按置信度决策"

```python
def check_confidence(score):
    """Verify confidence between 0 and 1"""
    if 0 <= score <= 1:
        return True
    return False

def make_decision(confidence):
    ...
```

**这是整个项目的核心思想的第一次落地**：
用一个 0~1 的分数表示"有多大把握"，再据此决定要不要作答。

### `day3.py` — 第 3 天：定下阈值

同样的两个函数，`make_decision` 里出现了具体阈值：

```python
if confidence >= 0.8:
```

**这就是"置信分阈值"的最早版本** —— 后来在 `src/day5.py` 里演变成 0~100 分制、
阈值 70，并加上了一整套抗干扰要求。

### `day4_plus.py` — 第 4 天：接入真实模型

第一次真正调用大模型接口，而且是**三个不同厂商**（DeepSeek / 智谱 / 通义）。

这里也确立了项目的密钥纪律（文件开头就写着）：

> 密钥一律从环境变量读取，绝不写进源码（避免提交到 GitHub 造成泄露）。

### `day5_verify.py` — 第 5 天：多模型交叉验证

让三个模型各自作答、再互相评审。

**这一版后来被证明有问题**：它每问要调 5~7 次 API，成本是单模型的 4.7 倍；
而且实测发现**裁判会给错误答案打满分**（见 `day5_cross_log.txt`）。

最终的解法在 `src/day5_pipeline.py`：换成**三段式流水线 + 程序层实体比对**，
成本降到每问 2 次，效果反而更好。

## 公开基准的失败尝试

| 文件 | 说明 |
|---|---|
| `truthfulqa_eval.py` | 在 TruthfulQA 上跑全量评测。**结果是失败的**：账户欠费导致 68% 题目异常，而且它依赖的自动判定器不可信 |
| `tqa_match.py` / `tqa_match2.py` | 两版自动答案判定器。**都不可靠** —— 它们分不清「模型主张某个错误说法」与「模型提到它但否定它」 |

**为什么保留失败的工具？**

因为这次失败本身是这个项目里最有价值的发现之一。完整复盘在
[`../reports/07_公开基准_失败复盘.md`](../reports/07_公开基准_失败复盘.md)：

> 那个判定器**通过了为它设计的全部验证（100%）**，
> 因为验证样本是"把错误答案抄一遍"—— 而真实模型会先复述误解再驳斥它。
> **100% 的通过率不是可靠性的证据，而可能是验证集太弱的信号。**

最终改用「挑 30 道最有迷惑性的题、逐条人工核对」，
见 [`../reports/06_公开基准_精选子集.md`](../reports/06_公开基准_精选子集.md)。

## 这条线怎么走到最终形态的

```
day1   print("Hello, confidence and safety!")
         ↓  只是起步
day2   第一次写出按置信度决策的函数
         ↓  有想法了
day3   定下阈值 0.8
         ↓  有规则了
day4   接入三个真实模型
         ↓  能跑真东西了
day5   完整的认识不确定性系统（自评 → 拒答 / 作答）
         ↓  核心机制成型
       ★ 然后发现：这个置信分本身并不可信
         ↓  于是有了验证层
       ★ 三段式流水线 + 程序层校验（最终形态）
         ↓
       现在的 ../src/
```

**注意中间那个转折**：做完 day5 之后，项目并没有直接"完工"，
而是**发现了自己方法的问题**（置信分不可信），再据此造出验证层。

**这个转折才是这个项目真正的价值所在。**
